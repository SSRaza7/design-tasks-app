# Задачи для дизайнеров — трекер (React + Supabase)

Полноценное веб-приложение: реальные аккаунты (баер/дизайнер), общая база задач,
загрузка креативов в файловое хранилище. Готово к публикации на Vercel.

## 1. Настройка Supabase

1. Зайдите на [supabase.com](https://supabase.com) → создайте новый проект (если ещё не создали).
2. Откройте **SQL Editor** → вставьте туда содержимое файла `supabase/schema.sql` из этого проекта → **Run**.
   Это создаст все таблицы, права доступа и хранилище для файлов одним махом.
3. Зайдите в **Authentication → Providers → Email** и выключите **"Confirm email"**
   (иначе для входа понадобится настраивать отправку почты — на старте это лишнее).
4. Зайдите в **Project Settings → API** и скопируйте:
   - **Project URL**
   - **anon public key**

## 2. Настройка проекта локально

```bash
npm install
cp .env.example .env
```

Откройте `.env` и вставьте туда значения из Supabase:

```
VITE_SUPABASE_URL=https://ваш-проект.supabase.co
VITE_SUPABASE_ANON_KEY=ваш-anon-key
```

Запустить локально для проверки:

```bash
npm run dev
```

Откроется на `http://localhost:5173` — зарегистрируйте первого баера и первого
дизайнера (кнопка «Зарегистрироваться» на экране входа, выбрав нужную роль),
чтобы проверить, что всё работает.

## 3. Деплой на Vercel

1. Загрузите этот проект в свой репозиторий на GitHub (создайте новый репозиторий,
   загрузите туда файлы).
2. Зайдите на [vercel.com](https://vercel.com) → войдите через GitHub → **Add New Project**
   → выберите этот репозиторий.
3. В настройках проекта на Vercel добавьте те же переменные окружения:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. **Deploy**. Через минуту получите рабочую ссылку вида `design-tasks-app.vercel.app`.

## 4. Свой домен (по желанию)

Купите домен на любом регистраторе (Namecheap, Reg.ru и т.д.) → в Vercel
зайдите в **Settings → Domains** проекта → добавьте свой домен → Vercel покажет,
какие DNS-записи прописать у регистратора. Обычно применяется в течение часа.

## Как выдавать доступ баерам и дизайнерам

Никакого отдельного «списка допуска» настраивать не нужно — это уже реальная
регистрация через Supabase Auth:

- Каждый человек сам заходит по ссылке на сайт → нажимает «Зарегистрироваться» →
  выбирает свою роль (баер/дизайнер) → вводит рабочую почту и пароль.
- Роль сохраняется в базе (`profiles`) и с этого момента задаёт, какой портал
  человек видит при каждом следующем входе.
- Если нужно кому-то поменять роль или заблокировать — это делается прямо в
  Supabase Dashboard → **Table Editor → profiles** (изменить/удалить строку)
  или **Authentication → Users** (удалить пользователя целиком).

## Структура проекта

```
src/
  lib/
    supabaseClient.js   — подключение к Supabase
    constants.js        — страны, языки, типы задач, статусы, цвета темы
  components/
    AuthScreen.jsx       — вход/регистрация
    TaskModal.jsx        — карточка задачи (создание/редактирование)
    SearchableSelect.jsx — выпадающий список с поиском (гео/язык)
    Field.jsx            — обёртки для полей формы
  App.jsx                — список задач, ролевая логика, подключение к БД

  schema.sql             — вся схема базы + права доступа + хранилище
```

## 5. Telegram-уведомления (по желанию)

Баерам приходит уведомление, когда дизайнер переводит задачу в статус
«На ревью». Дизайнерам приходит уведомление о каждой новой задаче.

### 5.1 Создать бота
1. В Telegram напишите **@BotFather** → `/newbot` → задайте имя и username.
2. Сохраните токен вида `123456789:AAH...`.

### 5.2 Выполнить миграцию базы
В Supabase → SQL Editor выполните `supabase/migration-telegram.sql`.

### 5.3 Задеплоить Edge Function
1. Supabase Dashboard → **Edge Functions** → **Deploy a new function**.
2. Имя функции: `notify-telegram`.
3. Вставьте содержимое `supabase/functions/notify-telegram/index.ts`.
4. Deploy.
5. В настройках функции (Secrets) добавьте:
   - `TELEGRAM_BOT_TOKEN` = токен из шага 5.1
   - `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` обычно доступны функциям
     автоматически; если Supabase попросит — возьмите их в
     Project Settings → API (Service role — секретный ключ, храните только
     в Secrets функции, никогда не в клиентском коде).
6. Отключите проверку JWT для этой функции (Function settings →
   **Verify JWT** → выключить), иначе вебхук от базы не сможет её вызвать.

### 5.4 Настроить Database Webhook
1. Supabase Dashboard → **Database** → **Webhooks** → **Create a new hook**.
2. Table: `tasks`. Events: **Insert** и **Update** (оба).
3. Type: **Supabase Edge Functions** → выберите `notify-telegram`.
4. Save.

### 5.5 Каждый участник включает уведомления себе
1. Найти вашего бота в Telegram → **Start**.
2. Написать **@userinfobot** → он пришлёт числовой ID.
3. В самом трекере — иконка шестерёнки в шапке → вставить этот ID → Сохранить.

Готово — с этого момента баер и дизайнеры получают пуши в Telegram
автоматически.

## Известные упрощения (можно доработать позже)

- Права в базе сейчас разрешают любому авторизованному пользователю
  редактировать/удалять любую задачу — разграничение баер/дизайнер работает
  только на уровне интерфейса. Для более строгой защиты можно сузить RLS-политики
  в `tasks`, добавив проверку роли через `profiles`.
- Смена роли или пароля пользователем через сам интерфейс не реализована —
  это делается через Supabase Dashboard вручную.
